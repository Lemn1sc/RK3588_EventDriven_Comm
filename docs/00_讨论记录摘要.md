## 课题

**基于 RK3588 的事件驱动无线通信**，三端架构：
- 事件端 — 产生有意义的触发信号
- GRU 控制端 — 基于时序信息做通信决策
- WiFi 无线传输 — 事件驱动下的实际通信

核心优势：只在"有意义"的时刻触发传输，相比周期性传输大幅降低带宽与延迟。

## 方案演进脉络（关键决策点）

1. **起点**：拟结合强化学习，AI 给了 4 个 RL 方向（多智能体避障 / 视觉异常检测 / 力反馈控制 / 联邦 RL）。
2. **硬件约束**：只有**一块板子** → 排除多智能体避障，转向单板场景。
3. **放宽方法**：确定**不一定用 RL**，GRU 可作预测器 / 异常检测器 / 分类器 / 调度器。
4. **职责收敛**：**事件端不用 GRU**，事件端用轻量方法（YOLO / 阈值 / 帧差），GRU 专注通信调度。
5. **最终方向**：聚焦"**算力不足 → 卸载**"场景——本地轻量模型初筛，GRU 判断本地搞不定时卸载到远端。

## 最终确定：算力卸载三组合

| 组合 | 本地 | 远端 | 特点 |
|------|------|------|------|
| 组合1 | yolov5n/yolo11n 检测 | yolov5m/yolo11m 检测 | 最简单，同任务不同精度 |
| 组合2 | yolov8n 检测 | yolov8m-seg 分割 | 任务级卸载 |
| **组合3 ★** | yolov8n 检测 | yolov8n-pose 姿态 | 跌倒检测，事件最稀疏，GRU 价值最大 |

**结论**：主攻组合3；用组合1 先快速跑通 pipeline。
