## 课题

**基于 RK3588 的事件驱动无线通信**，三端架构：

- **事件端** — 产生有意义的触发信号
- **GRU 控制端** — 基于时序信息做通信决策
- **WiFi 无线传输** — 事件驱动下的实际通信

核心优势：只在"有意义"的时刻触发传输，相比周期性传输大幅降低带宽与延迟。

## 方案演进脉络（关键决策点）

1. **起点**：拟结合强化学习，曾考虑 4 个 RL 方向（多智能体避障 / 视觉异常检测 /
   力反馈控制 / 联邦 RL）。
2. **硬件约束**：只有**一块板子** → 排除多智能体避障，转向单板场景。
3. **放宽方法**：确定**不一定用 RL**；GRU 可作预测器 / 异常检测器 / 分类器 / 调度器。
4. **职责收敛**：**事件端不用 GRU** —— 事件端用轻量方法（YOLO / 阈值 / 帧差），
   GRU 专注通信调度。
5. **最终方向**：聚焦"**算力不足 → 卸载**"——本地轻量模型初筛，GRU 判断本地搞不定时
   卸载到远端。

## 最终确定：算力卸载三组合

| 组合 | 本地 | 远端 | 特点 |
|------|------|------|------|
| 组合1 | yolov5n/yolo11n 检测 | yolov5m/yolo11m 检测 | 最简单，同任务不同精度 |
| 组合2 | yolov8n 检测 | yolov8m-seg 分割 | 任务级卸载 |
| **组合3 ★** | yolov8n 检测 | yolov8n-pose 姿态 | 跌倒检测，事件最稀疏，GRU 价值最大 |

**结论**：主攻组合3；用组合1 先快速跑通 pipeline。

> ⚠️ 后续实验对组合3 的一个前提提出了修正：**姿态并没有带来可测量的精度增量**
> （见 `docs/08` §14）。但「检测 + 时序决策」这条主线不变 —— GRU 的价值在
> **跨视角稳定性**，不在姿态确认。

## 2026-11-16 · 事件层与紧急度调度

老师提出“信道拥塞/质量差时优先传更紧急的事件”。落法是**事件驱动通信**，而不是继续
和检测器较劲：

- 事件层（用户负责）把逐帧检测变成**带生命周期的事件流**：`kind / state / start_ts /
  confidence / reliability / suggested_urgency / 载荷选项`；
- 低置信躺姿不再被硬阈值丢掉，而是“高紧急度 + 低可靠性”的事件 → 控制端先用几十字节
  的 metadata 抢通，再由远端请求 ROI/整帧确认；
- `TRACK_LOST` 把“检测器躺地失效”本身变成事件：MCF 单帧几何只能覆盖 8.8% 的跌倒事件，
  加上 `TRACK_LOST` 后事件级召回 67.9%（docs/09）；现在按“消失前变扁/下沉/是否贴边”
  打分，分数写进 `confidence`/`reliability`，控制端按带宽选工作点；
- 控制端（队友）负责信道状态、队列、优先级/截止时间调度；事件层只给建议，不做决策。

接口与结果见 **docs/09_事件层接口.md**；8 维向量布局不变。
