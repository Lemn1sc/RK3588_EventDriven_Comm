# T0.7 · 真实数据集首测记录（URFD · 2026-08-27）

> 目标：拿到真实跌倒视频，跑通"检测 → 事件向量 → 姿态判定"全流程，
> 用真实数据回答两个问题：**① 单帧高宽比触发器好不好使；② 姿态判定本身能不能分清跌倒和日常**。
>
> 结论先行：**两个问题答案都是"不能单独扛"**——单帧几何线索在 URFD 一号摄像头（低位视角）下
> 漏检严重，姿态判定单帧可达 67% 检出 / 20% 误报但分布重叠、无干净阈值。
> 这正好用真实数据验证了项目立项的核心动机：**需要 GRU 吃时序**。

## 2. 判定规则（本项目当前定义，docs/07 建议的几何量）

**触发**（事件端，单帧高宽比）：
```
severity = 检测置信度 × 高宽比异常度
异常度:  h/w ≥ 1.5 → 0（直立）；h/w ≤ 0.7 → 1（躺卧）；中间线性
severity ≥ 0.5 → SUSPECTED → 卸载调姿态
```

**判定**（远端 pose，任一命中即该帧判跌倒）：
```
① 框高宽比 h/w < 0.7
② 肩中点↔髋中点连线与垂直方向夹角 > 45°
③ 髋↔踝高度差 / 框高 < 0.3
```
关键点先按 `conf ≥ 0.3` 过滤，防遮挡 (0,0) 点污染。

## 3. 发现一：单帧高宽比触发器在 URFD cam0 上漏检约 90%

URFD 一号摄像头平行于地面（低位视角）。实测 30 段跌倒视频的**最大 severity** 分布：

| severity 区间 | 段数 | 视频 | 含义 |
|---------------|------|------|------|
| **≥ 0.5**（能触发级联） | **3/30** | fall-10(0.534), fall-08(0.554), fall-11(0.681) | 框真变扁了 |
| 0.25 ~ 0.5（边缘） | 8/30 | fall-12,13,03,24,04,09,02,22 (0.258~0.440) | 接近但触发不了 |
| 0.02 ~ 0.25 | 11/30 | fall-28,27,30,07,01,06,15,05,16,14,26 | 跌倒时框几乎不变扁 |
| **0.000（全程检不出人）** | **8/30** | fall-17,18,19,20,21,23,25,29 | 低位视角下人太矮/被遮挡 |

**结论：跌倒时包围框高宽比在 cam0 低位视角下不会显著下降，单帧 severity 触发器漏掉约 90% 的跌倒。**

> 这印证了 docs/06 记录的"纯高宽比无法区分真跌倒与画面截断"的已知局限，
> 并且是**更严重的版本**：不是"误报"，而是 cam0 下连跌倒本身都不触发。

## 4. 发现二：姿态判定单帧不能分清跌倒与日常

修掉判定公式 bug 后，70 段视频全帧跑 `检测 + 姿态`（`bench_pose_fall.py`，跌倒帧占比 ≥ 0.2 记检出）：

| 指标 | 数值 |
|------|------|
| 跌倒视频检出率 | **67%（20/30）** |
| 日常视频误报率 | **20%（8/40）** |
| fall 段跌倒帧占比区间 | 0.00 ~ 0.73 |
| adl 段跌倒帧占比区间 | 0.00 ~ 0.36 |

未检出的跌倒：fall-19(0.00), 21(0.02), 17(0.05), 23(0.07), 25(0.07), 27(0.09), 09(0.15), 29(0.15), 01(0.14), 13(0.16)。
误报的日常：adl-04(0.36), 01(0.27), 02(0.27), 05(0.26), 11(0.26), 09(0.24), 06(0.22), 17(0.22)。

**原因（本质）**：单帧几何上，「跌倒躺地」与「日常坐下 / 弯腰 / 躺卧 / 蹲起」的躯干倾角和髋踝高差**不可区分**。
ADL 里的躺卧类活动在几何上与跌倒完全同构——单帧不可能分开，只有时序（突变的瞬态 vs 平稳的状态）能分。

**这是项目用 GRU 处理时序的实证依据**，比任何仿真都更有说服力。

## 5. 过程中修的 3 个 bug（记录防踩坑）

| # | bug | 现象 | 修复 |
|---|-----|------|------|
| 1 | `cv2.rectangle(frame, (0,0,240,28), (0,0,240,28), ...)` 两点写成四元组 | 判到跌倒帧时崩溃（thickness 报错） | 改为 `(0,0),(240,28)` |
| 2 | ultralytics 偶发异常输出 `keypoints.xy` shape=(1,0,2) 且 `conf=None` | `len(k)=1` 守卫拦不住，空数组索引崩溃 | 加兜底：`kxy.ndim==3 and kxy.shape[1]>=4 and kconf.shape==kxy.shape[:2]` 才算几何 |
| 3 | **髋踝高度差公式符号错**：`max(hip_y - ankle_y, 0)` | 像素 y 向下，站立时 hip_y < ankle_y → 恒为 0 → **全帧误报**，基准数字全废 | 改为 `abs(hip_y - ankle_y) / bbox_h` |

> ⚠️ bug #3 的教训：凡涉及像素坐标系的方向性，先想清楚 y 轴方向再写 `max/abs`。
> 早期的 bench 结果（`bench_pose.csv`）基于错误公式，已作废，以 `bench_pose_v2.csv` 为准。

## 7. 结论与对后续阶段的指导

1. **T0.4 的"固定规则卸载"不能只用单帧高宽比**。cam0 类低位视角下必须引入时序触发
   （如相对自身近 30 帧基线的突降比），或先以 `--always-pose` 全帧跑姿态作为调试基线。
2. **T0.6 GRU 的监督标签**：URFD 这段镜像没有官方标注文件（原版官方标注含每帧
   跌倒起始/结束帧号，如需要完整标注需另取官方数据），目前可用"视频名 ∈ {fall, adl}"
   作粗粒度标签训练时序分类。
3. **姿态判定本身可作为远端"确认环节"保留**，但它单帧给的是"疑似度"而非"确定性"；
   最终结论应落在时序层。
4. 对比实验（T0.8）的卸载率应**以时序触发为准重新定义**，不能沿用纯 severity 门槛。

## 8. GRU 时序验证（初步实验记录 · 2026-08-30 · 结论未定）

> ⚠️ 本节是**一次可能的实验结果的记录与总结**，仅代表当前数据 / 划分 / 超参下的观察，
> **不视为最终结论**。数值带噪声（测试集小、弱监督），用作 T0.6 GRU 控制端设计的参考，
> 不是立项依据。若要下结论，需按 §8.6 补齐验证。

### 8.1 目的

承接 §3/§4 两个发现（单帧几何不可分、低位视角漏检），验证：**给同一批单帧特征
接一个简单 GRU 吃时序，跌倒/日常的分离度能否提升；以及"只靠检测特征"够不够**。

### 8.2 设置

| 项 | 内容 |
|----|------|
| 数据 | URFD 70 段（30 fall + 40 adl），每 seed 按视频随机划 52 训练 / 18 测试（防同视频泄漏） |
| 特征 det | 4 维/帧 = [has_event, confidence, severity, 框高宽比h/w]（仅 yolov8n，边缘端可用） |
| 特征 pose | 6 维/帧 = det 4 维 + [躯干倾角/90, 髋踝高差比]（需 yolov8n-pose，对照组） |
| 窗口 | 30 帧（≈1s）滑窗，步长 10；**标签用视频级弱监督**（URFD 镜像无帧级标注） |
| 模型 | GRU(hidden=32, 1 层) → 末帧隐状态 → 二分类 logit；BCE + Adam(lr=1e-3)，40 epoch，batch 64 |
| 视频级判定 | 每段取窗口概率最大值；ROC 对齐基线误报率比较 |
| 脚本 / 产物 | `scripts/train_gru_fall.py`；`models/pt/gru_fall_{det,pose}.pt`；特征缓存 `gru_features_{det,pose}.npz` |

### 8.3 结果 A：单次划分（seed=0，18 段测试）

| 特征源 | 单帧检出@零误报 | GRU@零误报 | GRU@FPR≤0.1 | AUC 单帧→GRU |
|--------|----------------|------------|-------------|--------------|
| det | 12% | 100% | 100% | 0.72 → 1.00 |
| pose | 62% | 75% | 100% | 0.89 → 0.98 |

### 8.4 结果 B：5 个 seed 稳健性（mean±std）

| 特征源 | 单帧检出@零误报 | GRU@零误报 | GRU@FPR≤0.1 | AUC 单帧→GRU |
|--------|----------------|------------|-------------|--------------|
| det | 8±6% | 68±22% | 80±13% | 0.715 → 0.887 |
| pose | 65±15% | 62±11% | 72±20% | 0.857 → 0.885 |

### 8.5 初步观察（tentative，按置信度排序）

1. **"仅检测 + 时序"价值最大、最稳**：det 单帧规则 ~8%（极差，对应 §3 漏检 90%），
   det GRU 拉到 ~68%、AUC 0.72→0.89。低位视角漏检的跌倒被时序捞回。
2. **det GRU ≈ pose GRU（平均）**：AUC 0.887 vs 0.885 几乎打平 → 支持"边缘端只靠
   检测特征+时序、姿态或可省"的架构假设，但 det 方差大（±22），**尚不能定论**。
3. **pose 单帧本身已不错**（65%），pose GRU 增益有限（AUC 0.86→0.89）→ 姿态一路的时序价值不大。
4. **单次划分不可信**：seed=0 时 det 出现 100% 的乐观值，多 seed 校正到 68±22%。

### 8.6 局限与未做事项（下结论前需补）

- 每 seed 测试集仅 8 段跌倒，@零误报类点数噪声大；可加 seed 数、或换 leave-one-video-out。
- 窗口标签是视频级弱监督；URFD 官方标注（逐帧 fall 起止）未获取，可考虑补标签做强监督。
- 未做：超参搜索、窗口长度/步长调优、时序特征工程（如 §7 建议的相对自身基线的突降比）。
- 未做：GRU 作为"卸载决策"的完整闭环实验（含信道/带宽，那是 T0.5/T0.6 控制端范围）。
- 未做：财务室自采数据 / Le2i Office 场景的跨场景验证。
