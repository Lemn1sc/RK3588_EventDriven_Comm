# 技术方案

## 1. 三端架构

```
┌──────────────── RK3588（边缘端） ────────────────┐        WiFi         ┌──── PC / 另一块板（远端） ────┐
│                                                   │                     │                              │
│  摄像头 → yolov8n 检测(NPU) → 检测框+置信度        │   事件驱动卸载       │   yolov8n-pose 姿态估计       │
│                     ↓                             │  ─────────────►     │            ↓                 │
│              GRU 控制端                            │   (仅疑似异常帧)     │      17 关键点               │
│      输入: 检测框时序 + 信道状态 + 远端延迟历史     │  ◄─────────────     │            ↓                 │
│      输出: 本地处理 / 卸载 ; 传输时机 ; 压缩级别    │    结果回传          │   跌倒/异常判定 → 报警         │
│                     ↓                             │                     └──────────────────────────────┘
│              WiFi 传输端 (UDP + 优先级队列)         │
└───────────────────────────────────────────────────┘
```

## 2. 三端职责

### 事件端（检测层）
- 输入：摄像头帧（30fps）
- 处理：NPU 跑 yolov8n
- 输出：**8 维事件向量**（不做任何通信决策）

事件向量定义（`src/common` 里统一实现）：

| 索引 | 字段 | 含义 |
|------|------|------|
| 0 | event_type | 类别编号（0=无事件） |
| 1 | confidence | 检测置信度 |
| 2-5 | bbox | 归一化边界框 x1,y1,x2,y2 |
| 6 | has_event | 是否有事件（二值） |
| 7 | severity | 综合严重程度 |

### GRU 控制端（决策层）
- 输入：近 N 步事件向量序列 + 当前信道状态（RSSI/RTT/丢包）+ 远端延迟历史 + 队列状态
- 输出（多任务头）：
  - transmit：不传 / 摘要 / 关键帧 / 视频片段（或卸载/不卸载）
  - timing：立即 / 延迟等待信道改善
  - compress：高 / 中 / 低压缩
- 价值：事件突发时的优先级排序、信道波动时的择机传输、区分正常动作与异常（时序）

### WiFi 传输端（执行层）
- 优先级队列 + UDP 打包 + 轻量重传
- 采集信道质量反馈给控制端

## 3. 三个卸载组合

### 组合1：轻量检测 + 重量级检测（最简单，先跑通用）
- 本地 yolov5n/yolo11n，远端 yolov5m/yolo11m
- 事件：置信度 >0.7 本地；0.3~0.7 由 GRU 决定；多目标重叠触发卸载

### 组合2：检测 + 分割
- 本地 yolov8n，远端 yolov8m-seg
- 事件：目标进入危险区域 / 需精确轮廓时卸载
- GRU 编码轨迹，预判目标即将进入危险区提前卸载

### 组合3：检测 + 姿态（★ 主攻，跌倒检测）
- 本地 yolov8n（有没有人），远端 yolov8n-pose（关键点）
- 事件：
  - 无人 → 不通信
  - 有人正常行走 → 不通信
  - 停留超时 / 检测框高宽比突变 / 位置异常 → 卸载确认
- GRU 编码检测框时序（位置、大小、高宽比），区分"正常蹲下"与"跌倒"

## 4. GRU 控制端模型（参考实现）

```python
import torch, torch.nn as nn

class GRUOffloadController(nn.Module):
    """GRU 决定是否将推理任务卸载到远端"""
    def __init__(self, state_dim=12, hidden_dim=64):
        super().__init__()
        self.gru = nn.GRU(input_size=state_dim, hidden_size=hidden_dim,
                          num_layers=1, batch_first=True)
        self.decision_head = nn.Sequential(
            nn.Linear(hidden_dim, 32), nn.ReLU(),
            nn.Linear(32, 2)  # 0=本地, 1=卸载
        )
    def forward(self, state_seq, hidden=None):
        output, hidden = self.gru(state_seq, hidden)
        return self.decision_head(output[:, -1, :]), hidden
```

状态向量（12 维）：本地置信度、目标数、面积占比、场景复杂度、远端最近 4 次 RTT、RSSI、当前 RTT、丢包率、NPU 负载。

## 5. 训练方式（不用 RL）

监督学习：
1. 用仿真器（`src/simulator`）生成带"事后最优决策"标签的事件流 + 信道序列
2. GRU 拟合最优决策（CrossEntropy 多任务损失）
3. 后续可选：换成 RL（SB3/CleanRL）做在线优化

## 6. 对比实验设计

| 方法 | 描述 | 预期传输率 |
|------|------|-----------|
| 周期传输 | 每帧都传 | 100% |
| 固定降采样 | 每 5 帧传 1 帧 | 20% |
| 固定阈值事件触发 | 置信度>0.5 就传 | ~10-15% |
| GRU 自适应（本方案） | 综合事件+信道决策 | ~5-8% |

评估：传输率、事件检出率、平均延迟、漏报/误报率、信道利用效率。

数据集：`UR Fall Detection` / `Le2i Fall Detection`（离线可复现实验）。
