# 开发路线图

> 按"能否脱离板子"分组。M0 是当前阶段，尽量把算法与系统逻辑全部在 PC 上做完。

## M0 · 无板子阶段（当前，PC 上完成）

详见 `04_无板子阶段任务.md`。概览：

- [ ] T0.1 环境搭建：Python 环境 + ultralytics（Windows 可直接跑）
- [ ] T0.2 跑通 yolov8n 检测、yolov8n-pose 姿态，看清输出格式
- [~] T0.3 定义事件向量 / 状态向量 / 通信协议（`src/common`）
      — 事件向量(8 维)已完成并验证；状态向量(12 维) / UDP 协议待队友
- [ ] T0.4 localhost 双进程 pipeline：edge_node ↔ remote_node（`src/transport`）
- [ ] T0.5 事件 + 信道仿真器，生成 GRU 训练数据（`src/simulator`）
- [ ] T0.6 GRU 控制端定义 + 训练（`src/controller`）
- [ ] T0.7 下载跌倒数据集，接入离线视频源（`data/`）
- [ ] T0.8 对比实验框架：4 条基线 + 指标统计 + 出图（`experiments/`）
- [ ] T0.9（可选）WSL2 + rknn-toolkit2 装好，用 simulator 验证转换数值精度

产出：一份能在纯 PC 上跑出对比数据的完整原型 + 一套可移植代码。

## M1 · 板端基础（需板子，1-2 天）

- [ ] 查 `cat /proc/rknpu/version`，锁定 rknn-toolkit2 版本
- [ ] yolov8n ONNX → RKNN（先 FP16 不量化）
- [ ] 板端 RKNNLite 加载 + 单张图推理跑通
- [ ] 摄像头接入，实时检测

## M2 · 通信打通（需板子，1-2 天）

- [ ] 把 M0 的 transport 模块部署到真机
- [ ] 板（edge）↔ PC（remote）真实 WiFi UDP 收发
- [ ] 采集真实信道指标（iwconfig / ping RTT）反馈控制端

## M3 · 固定规则版（需板子，1-2 天）

- [ ] 用固定阈值卸载逻辑替代 GRU，端到端演示
- [ ] 此时已可展示事件驱动 vs 周期传输的基本优势

## M4 · GRU 上板（需板子，3-5 天）

- [ ] GRU 控制端 ONNX → RKNN，分配到 NPU_CORE_1
- [ ] 事件端 YOLO 用 NPU_CORE_0，避免抢占
- [ ] 替换固定规则，真机实时决策

## M5 · 对比实验（需板子，1 周）

- [ ] 真机跑四基线，录制 10 分钟含 5-10 次事件的场景
- [ ] 统计带宽 / 延迟 / 漏报 / 误报，出对比图

## M6 · 论文 / 结题（持续）

- [ ] 整理指标图表
